# 苹果微信视频兼容与正负视频分组设计

## 背景

生产环境在 2026-08-25 新增了 37 条培训视频。安卓微信和鸿蒙能够播放，但苹果微信对部分视频报“当前微信不支持这个视频地址或格式”。同一批视频在公开资料页中也按单条记录连续排列，手机用户无法先区分正向示范和负向示范。

本次调整同时解决两个问题：

1. 为苹果微信提供稳定、可渐进播放的视频版本。
2. 在后台和公开资料页中明确区分正向视频与负向视频。

## 已确认事实

- 截图中的“整理桌面 卧室”文件约 253 MB，视频编码为 H.265/HEVC，分辨率为 1920x1440。
- 对全部 37 条生产视频进行媒体探测后，大部分为 HEVC，少部分为 H.264；所有文件都是 1920x1440。
- 文件的 `moov` 播放索引位于 MP4 末尾，部分 H.264 文件还报告 `wrong sample count`。
- Supabase 原始地址与 Vercel `/training-media/` 转发地址均正确返回 `200/206`、`Accept-Ranges: bytes`、`Content-Range` 和 `Content-Type: video/mp4`。
- 因此故障不在登录、分享令牌、Supabase 容量或 Range 请求，而在上传链路没有规范化视频编码、尺寸和 MP4 结构。
- 现有 37 条记录中，24 条章节标题以“正向视频”开头，13 条以“负面视频”开头；当前临时使用“沟通表达/专业能力”作为两组分类。

## 目标

- 现有分享链接保持不变。
- 不删除、不覆盖 37 条原始视频。
- 苹果微信优先播放 H.264 兼容副本。
- 安卓、鸿蒙和桌面浏览器仍可使用原始视频，并在失败时自动尝试兼容副本。
- 新视频上传后自动产生兼容副本，不再依赖管理员手工转换。
- 新建或编辑课程时可选择“正向视频”或“负向视频”。
- 手机公开页首次进入默认显示正向视频，用户可在页面顶部切换负向视频，两组记录不混排。

## 非目标

- 本次不删除原视频，也不压缩或迁移原视频地址。
- 本次不引入付费视频平台，不改变 Supabase Storage 供应商。
- 本次不修改动作流、文字稿、笔记和分享令牌的数据结构。
- 本次不重构培训学堂其他课程、报名、学习路径和统计功能。

## 视频兼容方案

### 兼容格式

兼容副本统一满足以下约束：

- MP4 容器。
- H.264/AVC 视频，`avc1` 标签，High Profile，Level 4.1。
- `yuv420p` 像素格式。
- 等比例缩放到不超过 1920x1080，宽高为偶数。
- 如存在音轨则转为 AAC-LC；无音轨时保持无音轨。
- 使用 `faststart`，将 `moov` 索引移动到文件开头。

### 存储路径

原视频路径保持不变，例如：

`training-materials/materials/1787647686320-9911fd35.mp4`

兼容副本使用确定性路径：

`training-materials/materials/ios-compatible/1787647686320-9911fd35.mp4`

确定性路径避免修改课程 JSON 和分享链接，也让播放器能够直接从原始 URL 推导兼容 URL。重复任务在兼容文件已经存在时跳过，因此处理是幂等的。

### 播放器候选顺序

播放器不再只保存一个主线路和一个备用线路，而是保存有序候选地址：

- iPhone/iPad 微信：兼容副本、Supabase 原地址、Vercel 转发地址。
- iPhone/iPad Safari：兼容副本、Supabase 原地址、Vercel 转发地址。
- 安卓/鸿蒙微信：Vercel 转发地址、Supabase 原地址、兼容副本。
- 其他浏览器：Supabase 原地址、Vercel 转发地址、兼容副本。

同一地址只保留一次。某一线路触发媒体错误或超时后，播放器切换到下一候选地址；用户仍通过明确的播放按钮启动有声音的视频，遵守 iOS 用户手势限制。

### 自动兼容处理

当前生产架构只有 Vercel 静态前端和 Supabase Edge Functions，它们都不适合执行数分钟的 FFmpeg 转码。为避免引入新的付费供应商，使用 GitHub Actions 作为异步媒体处理器：

1. 定时任务和手工任务读取公开课程清单。
2. 找出 Supabase `training-materials` 中尚无兼容副本的视频。
3. 每次顺序下载一个源文件到临时目录。
4. 使用 FFprobe 记录源编码，使用 FFmpeg 生成兼容 MP4。
5. 使用 Supabase TUS resumable upload 上传到确定性兼容路径。
6. 使用 HEAD 和 FFprobe 验证上传文件的状态、编码、尺寸和 fast-start 结构。
7. 删除运行器上的临时文件后处理下一条。

仓库只保存 Supabase URL；`SUPABASE_SERVICE_ROLE_KEY` 保存为 GitHub Actions Secret，不写入源码、日志或前端。工作流使用并发锁，避免同一视频被多个任务重复处理。单个视频失败不会删除原件，也不会阻塞其他视频；任务以失败状态结束并在日志中列出文件名。

## 正向与负向分类

### 数据约定

沿用 `training_courses.category`，新增两个合法值：

- `正向视频`
- `负向视频`

这样无需新增数据库字段或迁移表结构，也符合用户在“分类维度”中直接选择的操作方式。原有“沟通表达、专业能力、应变能力、综合素质、综合”继续保留，避免影响培训学堂的历史课程。

### 现有数据回填

只更新符合明确章节标题规则的记录：

- 章节标题以“正向视频”开头：课程分类改为 `正向视频`。
- 章节标题以“负向视频”或“负面视频”开头：课程分类改为 `负向视频`。
- 没有匹配规则的课程保持原分类。

回填前记录课程 ID、旧分类和新分类；更新后重新读取 37 条记录，预期结果为正向 24、负向 13。视频 URL、课程 ID、动作流和分享令牌不参与更新。

## 后台交互

- 新建与编辑课程的“分类维度”下拉框增加“正向视频”和“负向视频”。
- 视频分享管理页的分类筛选自动显示 `全部 37 / 正向视频 24 / 负向视频 13`。
- 列表卡片继续显示分类标签，使管理员不进入详情也能识别属性。
- 现有搜索、分页、打开、复制链接、动作流、编辑和删除操作保持不变。

## 手机公开页交互

公开 `/video-sharing` 页面增加一级“视频属性”切换区，位于统计信息之后、搜索框和记录列表之前：

- `正向视频 24`
- `负向视频 13`
- `其他资料`（只在存在未分类视频或文档时显示）

手机首次打开默认选中“正向视频”，列表只渲染正向记录。切换到“负向视频”后只渲染负向记录，不提供会把正负视频混排的默认“全部”视图。桌面端可以额外显示“全部”，但默认同样为正向视频。

文件类型筛选作为二级筛选保留，用于在当前属性中选择视频、文档、PDF 或 Word；搜索只搜索当前属性中的记录。分类切换按钮使用固定高度和横向滚动，适配窄屏微信 WebView。

## 错误处理

- 兼容副本尚未生成或返回 404：播放器自动尝试原地址，并显示正在切换线路，不把 404 暴露给学习者。
- 所有候选线路均失败：显示具体媒体错误与“重新播放”，保留直接打开原视频的入口。
- 转码失败：保留原视频和课程数据，GitHub Actions 输出失败文件清单，可安全重跑。
- 分类无法从章节标题推断：不自动修改，归入“其他资料”。
- 公开课程接口失败：保持现有网络错误提示，不显示错误计数。

## 测试与验收

### 自动测试

- 由原始 Supabase URL 正确推导兼容副本 URL。
- iOS 微信、iOS Safari、安卓微信和桌面浏览器得到正确且去重的候选顺序。
- 正向、负向、负面章节标题正确归类，普通课程不被误分类。
- 手机默认筛选为正向视频，切换负向后不会包含正向记录。
- FFmpeg 参数包含 H.264、AAC、1080 高度限制、`yuv420p` 和 `faststart`。
- 已存在兼容副本时处理器跳过，失败时不会覆盖源文件。

### 生产验收

- 37 条源对象在修复前后都存在且 ETag/大小不变。
- 37 条兼容对象均返回 `200/206`、`video/mp4` 和 `Accept-Ranges: bytes`。
- FFprobe 验证兼容对象为 H.264、最大高度不超过 1080、`yuv420p`。
- MP4 结构验证 `moov` 位于 `mdat` 之前。
- 苹果微信打开“整理桌面 卧室”以及至少一条正向视频能够点击播放、拖动进度和再次播放。
- 安卓微信、鸿蒙浏览器、Safari 和主流桌面浏览器的公开页、分类切换和播放入口正常。
- 公开页无需登录，原分享链接继续返回同一课程。
